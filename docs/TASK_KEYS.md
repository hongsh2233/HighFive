# 업무 고유 번호

모든 HighFive 업무는 `HF-000123` 형태의 고유 번호를 사용한다. `HF`는 HighFive 공통 접두어이며, 뒤 숫자는 해당 데이터베이스의 `Task.id`를 최소 6자리로 표시한 값이다. 100만 이상의 번호도 잘리지 않는다.

- 기존 업무는 별도 데이터 수정 없이 번호가 표시된다.
- 일반 업무, 그룹과 하위 업무, 파일 가져오기, 반복 자동 등록, 문의 전환은 모두 DB의 기존 자동 증가 id를 기준으로 각각 번호를 받는다. 별도 MAX+1 계산이나 카운터가 없으므로 동시 등록에 대한 중복 발급 경로를 추가하지 않는다.
- 제목/담당자/프로젝트/상태를 바꿔도 번호는 유지된다. 일반 삭제는 DB 시퀀스를 초기화하지 않으므로 삭제된 번호를 재사용하지 않는다. 번호는 연속성을 보장하지 않으며 조직별로 1부터 시작하지 않는다. 서로 다른 HighFive 설치 간의 전 세계 유일 번호는 아니다.
- 외부 시스템의 `rmsNo`는 별도 필드로 유지한다. 사용자가 등록/수정 요청에 보낸 `taskKey`는 저장하지 않는다. 숫자 `id`와 기존 `/tasks/123` 링크도 유지한다.

## 화면과 연동

- 목록, 전체 상세, 빠른 상세, 칸반, HOME/내 업무/프로젝트의 업무 카드와 업무 보기 캘린더, 통합 검색 결과에 번호가 표시된다.
- 통합 검색에 `HF-000123` 또는 `hf-123`을 입력해 업무를 찾는다. 기존 제목/본문 검색도 유지한다.
- 업무 목록/상세/등록/수정/상태 변경/캘린더 API 응답에는 `taskKey`가 추가된다. 그룹 등록 응답은 `subTasks`에도 각각 포함한다. 문의 전환 응답은 `taskId`와 `taskKey`를 제공한다.
- `/api/tasks?taskKey=HF-000123`는 정확한 번호 조회다. 번호를 알아도 기존 조직·역할·서비스 허용 프로젝트 권한을 벗어나지 않는다. 잘린/0/음수/Int 범위 초과 번호는 400으로 거부한다.
- CSV/XLSX 내보내기에 `업무번호` 열을 추가하고 기존 `ID`/`RMS번호` 열을 유지한다. JIA 댓글 초안과 연결된 GitHub 완료 댓글에도 번호를 포함한다.
- 브랜치/커밋/PR/배포 목록에 동일 번호를 기록해 업무와 변경을 연결할 수 있다. 예: 커밋 `[HF-000123] 로그인 오류 수정`. Git 번호 연동을 강제하거나 Jira 연동을 추가한 것은 아니다.

## 구현과 배포

공통 규칙은 `src/lib/task-key.ts`이며 DB 필드를 추가하지 않고 기존 불변 id에서 계산한다. `src/types/index.ts`의 `Task.taskKey`는 이전 서버와의 호환을 위해 선택 필드이고 UI는 id에서 직접 계산하므로 이전 응답도 표시한다.

HighFive 앱 서버를 최신 코드로 재빌드·재시작하면 반영된다. 이 기능에는 DB 마이그레이션이나 업무 재등록이 필요 없다. hanjia의 검수 문서 커밋 `1e00ec6`와는 별개로 **HighFive 저장소의 코드 배포**가 필요하다. 운영 서버에는 이 작업에서 접근하거나 배포하지 않았다.

## 검증 (2026-10-12)

- Vitest 14개 파일 / 82개 테스트 통과: 번호 불변성, 신규/하위/그룹 응답, 범위 밖 번호 거부, 번호 검색의 조직·역할 범위와 기존 회귀 검사.
- 최종 상세 표시 정리 후 관련 컴포넌트 13개 테스트 재검증 통과.
- Playwright: 로컬 운영 빌드 + 모의 API로 칸반/목록/전체 상세의 같은 번호 표시, 기존 흐름과 태블릿 가로 넘침 등 6개 시나리오 검사. 실제 운영 DB/계정의 검증은 별도로 필요하다.
- `npm run lint`, `npm run typecheck`, `npm run build` 통과. 기존 lint 경고 10건 및 bcryptjs의 crypto 해석 빌드 경고가 있으며 오류로 종료되지는 않았다.
